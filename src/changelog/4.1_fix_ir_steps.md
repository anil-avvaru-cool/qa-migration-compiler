# 4.1 — Fix IR steps (action, targetId, input)

Date: 2026-02-24

Summary
-------
Root cause: upstream extraction (ActionMapper) sometimes emitted insufficient step metadata (no semantic action verb, no reliable target reference). As a result `TestIR` files contained steps with `action: generic`, `targetId: null`, and `input: null`.

What I changed
--------------
- `src/extraction/action_mapper.py`
  - Emit both the canonical `action` (semantic verb) and legacy `name` (original member/method name).
  - Add `target_name_id` when page-object method patterns are detected (e.g. `enterUsername` -> `username`) to help `StepEnricher` resolve `targetId`.
  - Include debug logs of mapped steps for traceability.

- `src/extraction/locator_extractor.py`
  - Add legacy `strategy` field (original By.* method) for backward compatibility with tests that expect `strategy`.

- `src/ir/builder/test_ir_builder.py`
  - Accept legacy `name` as action when `action` is missing.
  - Fall back to using `target_name_id` directly as `targetId` when a mapping is not provided (helps unit tests and simple flows).

- `src/extraction/step_enricher.py`
  - Already present and used; the new `target_name_id` output from `ActionMapper` ensures the enricher can find `targetId` from locators.
