# Root Cause Analysis: "toProducts" targetId Issue

## The Problem

In `testAddProductToCart.json`:
```json
{
  "stepId": "STEP_01",
  "action": "navigate",
  "targetId": "toProducts"  ❌ NOT in targets.json
}
```

But `targets.json` has no entry with `targetId: "toProducts"`. This is a **reference integrity violation**.

---

## Root Cause Diagnosis

### 1. Source Code (ProductPage.java)

```java
public void navigateToProducts() {
    driver.get("https://ecommerce-app.localhost/products");  ← URL is HERE
    waitForPageToLoad();
}
```

The test calls: `productPage.navigateToProducts()`

### 2. How ActionMapper Processes It

**Current Flow:**
```
AST Node: MethodInvocation(navigateToProducts)
  ↓
1. Infers action from method name pattern "navigate.*" 
   → action_type = "navigate" ✅
  ↓
2. Tries to extract URL via _extract_navigate_target(node)
   → Looks for node.properties.value containing URL
   → ERROR: Method call AST node has NO URL in its properties! ❌
   → step_target = null ❌
  ↓
3. Falls back to deriving target_name_id from method name
   → Strips "navigate" from "navigateToProducts"
   → Gets "toProducts"
   → target_name_id = "toProducts" ⚠️
  ↓
4. Output Step:
   {
     "action": "navigate",
     "target": null,           ← NO URL FOUND
     "target_name_id": "toProducts",  ← FALLBACK NAME
     "targetId": null
   }
```

### 3. Why It's Wrong

**The Issue:** ActionMapper only sees the **method call**, not the **internal implementation**.

```
navigateToProducts() call (visible to ActionMapper)
    ↓
    └─→ Internal: driver.get("https://...") (NOT visible to ActionMapper)
```

So:
- ✅ ActionMapper correctly infers `action: "navigate"`
- ❌ ActionMapper CANNOT extract the URL because it's inside the method body
- ⚠️ ActionMapper falls back to `target_name_id: "toProducts"` (method name)
- ❌ But "toProducts" is NOT a UI element in targets.json (it's a method name!)

### 4. Why targets.json Doesn't Have "toProducts"

**LocatorExtractor only finds `By.*` selectors:**

```java
// What LocatorExtractor looks for:
private By searchInput = By.id("searchBox");           ← FINDS THIS
private By searchButton = By.xpath("//button[@id='searchBtn']");  ← FINDS THIS

// What it does NOT find:
public void navigateToProducts() {
    driver.get("https://...");  ← NOT A LOCATOR, WON'T EXTRACT
}
```

Result: No "toProducts" entry in targets.json ✅ (correct)

---

## The Mismatch

| Component | Sees | Result |
|-----------|------|--------|
| **ActionMapper** | `productPage.navigateToProducts()` | Emits `target_name_id: "toProducts"` |
| **LocatorExtractor** | Only `By.*` selectors | Doesn't extract "toProducts" |
| **StepEnricher** | Tries to resolve "toProducts" | Fails (not in targets.json) |
| **TestIRBuilder** | Gets unresolved targetId | Outputs `targetId: "toProducts"` |
| **IR Integrity** | Reference check | ❌ FAILS — "toProducts" not in targets.json |

---

## Why This Happens (Design Issue)

**Current ActionMapper behavior:**
1. For `driver.get(url)` calls → can extract URL ✅
2. For `navigate*` methods → assumes they're locators ❌

**But page object methods like `navigateToProducts()` are NOT locators:**
- They're navigation logic encapsulated in a method
- The actual URL is inside the method body
- ActionMapper can't see inside the method (would need call graph)

---

## Solutions

### Option A: Intercept at AST Level (Requires Call Graph)

**Idea:** Follow method calls to internal `driver.get()` statements.

**Example:**
```python
# In ActionMapper._extract_navigate_target():
if action_type == "navigate" and is_page_object_call:
    # Resolve the method call to find internal driver.get()
    internal_calls = call_graph.resolve_method_body(node)
    for call in internal_calls:
        if call.member == "get" and call.qualifier == "driver":
            return extract_url(call)  # Get URL from call
```

**Pros:** Precise, follows actual code
**Cons:** Requires CallGraphBuilder (complex), slower

---

### Option B: Smart Fallback in StepEnricher

**Idea:** When `target_name_id` cannot be resolved as a targetId:
- Mark it as a navigation method reference (not a UI element)
- Store as metadata instead of forcing targetId lookup

**Example:**
```python
# In StepEnricher._resolve_target_id():
if action == "navigate" and not resolved_id:
    # This is likely a method name, not a locator
    return {
        "type": "navigation_method",
        "value": target_name_id,  # e.g., "toProducts"
        "resolved": False
    }
```

**Pros:** Simple, backward compatible
**Cons:** Changes schema, adds complexity

---

### Option C: Warn & Auto-Fix in Pipeline

**Idea:** Detect unresolved navigation targetIds and log warnings.

```python
# In pipeline post-processing:
for test in all_tests:
    for step in test.steps:
        if step.action == "navigate" and step.targetId and step.targetId not in targets_by_id:
            logger.warning(
                f"Step {step.stepId}: navigation targetId '{step.targetId}' "
                f"not found in targets.json. This is likely a method name, not a locator. "
                f"Consider mapping it to a URL or ignoring it."
            )
            # Option: remove targetId or convert to "unknown_method" placeholder
```

**Pros:** Visible, actionable feedback
**Cons:** Leaves issue in IR

---

### ✅ Recommended: Option A (Call Graph)

**Action Items:**

1. **In ActionMapper, for `navigate*` page object methods:**
   - Check if call graph is available
   - If yes: follow method to `driver.get()` inside
   - Extract URL from there
   - Return proper `target: {type: "url", value: "https://..."}`
   - Skip `target_name_id` derivation

2. **If call graph unavailable:**
   - Log warning about unresolvable navigation method
   - Output best-effort targetId (current behavior)

3. **In TestIRBuilder:**
   - Validate: if `action: "navigate"`, then `target` should be non-null
   - If both `target` and `targetId` are null → log error
