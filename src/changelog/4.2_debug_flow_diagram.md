## Root Cause Analysis (The Problem)

### Original Issue from User

Generated `testValidLogin.json`:
```json
{
  "steps": [
    {
      "action": "generic",        ❌ WRONG
      "input": null,              ❌ WRONG
      "targetId": null            ❌ WRONG
    },
    {
      "action": "generic",
      "input": null,
      "targetId": null
    },
    {
      "action": "generic",
      "input": null,
      "targetId": null
    }
  ]
}
```

### Root Causes

1. **ActionMapper** emitted `"action": "generic"` as fallback when pattern matching failed.
   - No `target_name_id` to help downstream enricher.
   - Couldn't extract `input` without semantic context.

2. **StepEnricher** not invoked in the pipeline before TestIRBuilder.
   - Steps never got enriched with resolved targetIds.
   - Input fields never resolved from method parameters.

3. **TestIRBuilder** had no enricher to consume, so built incomplete IR.

### Solution Strategy

✅ **Upstream Fix** (preferred approach):
- Enhanced ActionMapper to emit semantic actions + `target_name_id`.
- Created/enabled StepEnricher to resolve targetIds and inputs.
- Fixed TestIRBuilder to accept enriched step structure.

This yielded **cleaner IR** and **simpler downstream generators**.

## Debug Checklist

When things go wrong, check in this order:

### 1. AST Parsing
- [ ] Does JavaParser handle the Java file syntax?
  - Check: `app.log` for parse errors.
  - Test file: `src/parser/java/java_parser.py` with a simple Java snippet.

### 2. LocatorExtractor
- [ ] Are `By.cssSelector()`, `By.xpath()` calls being found?
  - Check: Extracted targets have `targetId`, `selectorStrategies`, `context.page`.
  - Add debug log in `_extract_page_class()` to confirm page class name.

### 3. ActionMapper
- [ ] Are test method calls mapping to semantic actions?
  - Check: Extracted steps have `action` != "generic" and `target_name_id` is populated.
  - Add debug: log each node's `member` and inferred `action_type`.

```python
logger.debug(f"Node {node.id}: member={member}, action={action_type}, target_name_id={target_name_id}")
```

### 4. StepEnricher
- [ ] Are `target_name_id` values resolving to actual targetIds?
  - Check: After enrichment, steps have non-null `targetId`.
  - Debug: Log fuzzy matching attempts:
    
```python
logger.debug(f"Resolving target_name_id '{target_name_id}' → targetId='{resolved}'")
```

### 5. TestIRBuilder
- [ ] Are priority/severity inferred correctly?
  - Check: Test name contains keywords like "smoke", "login", "edge".
  - Add log: `_infer_priority()` and `_infer_severity()`.

### 6. FileWriter
- [ ] Are modular JSON files written to `output/ir/`?
  - Check: Directory structure exists.
  - Validate JSON: `python -m json.tool output/ir/targets.json`.
